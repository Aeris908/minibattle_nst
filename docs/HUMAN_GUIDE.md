# Руководство оператора: что требует участия человека

Это короткая инструкция для того, кто запускает конвейер и проверяет результат. Автоматика делает максимум, но калибровка, спорные атрибуции и подтверждение минибатлов остаются за человеком.

---

## 1. Что подготовить один раз

1. **Windows + Python 3.10+**, зависимости из `requirements.txt`.
2. **ffmpeg.exe** и **ffprobe.exe**. Либо добавьте их в `PATH`, либо задайте:
   ```cmd
   set GOAL3_FFMPEG=C:\ffmpeg\bin\ffmpeg.exe
   set GOAL3_FFPROBE=C:\ffmpeg\bin\ffprobe.exe
   set GOAL3_FFMPEG_LOCATION=C:\ffmpeg\bin
   ```
3. Запустите `pip install -r requirements.txt`.
4. Модели Whisper/easyocr при первом запуске скачиваются в локальный кэш. Для офлайн-режима:
   ```cmd
   set GOAL3_WHISPER_LOCAL_ONLY=1
   ```

---

## 2. Калибровка UI — обязательный ручной этап

Layout у разных стримеров разный. Калибровка делается один раз для конкретной раскладки.

```cmd
python tools\calibrate_ui.py --video path\to\sample.mp4 --time 45
```

В окнах OpenCV выберите:

1. **Playfield** — зелёное поле эмулятора без правой панели.
2. **Scoreboard anchor** — табло целиком, включая обе цифры счёта.
3. **Левую цифру счёта** — в увеличенном виде.
4. **Правую цифру счёта** — в увеличенном виде.
5. **Roster overlay** — правую плашку со списком игроков.
6. **Lineup screen** — область экрана расстановки до первого матча.

После выбора каждой цифры введите, какая цифра сейчас на табло. Пустой ввод пропускает шаблон.

Затем **доберите шаблоны всех цифр 0–9** с кадров, где они видны:

```cmd
python tools\calibrate_ui.py --capture-digit 3 --video path\to\video.mp4 --time 610
```

Проверьте, что для всех десяти цифр есть хотя бы один шаблон. Иначе голы с такой цифрой не прочитаются, а минибатл уйдёт в `needs_review`.

### Если команда войса сверху, а не снизу

По умолчанию **верхняя команда** на правой плашке считается `VOICE_TEAM`. Если у вас наоборот:

```cmd
set GOAL3_TOP_TEAM_ROLE=OPPONENT_TEAM
```

Это надо задать до запуска воркера.

## 3. Команды и лимиты, которые нужно знать

- В одном видео может быть **до двух и более минибатлов**. Воркер скачивает видео один раз, один раз проходит OpenCV, затем сам делит матчи на минибатлы по длине видео/длинным паузам и лимиту **9 матчей**.
- В каждом минибатле — до **12 игроков** (по 6 на сторону).
- Одна итерация воркера по умолчанию — **одно исходное видео**.
  - `python worker.py` — обработать одно видео;
  - `python worker.py --limit 0` — всю очередь;
  - `python worker.py --loop` — ждать новые видео и обрабатывать очередь.
- `python worker.py --video-id YOUTUBE_ID --force` — переобработать конкретное исходное видео.
- После ошибки/остановки можно вернуть зависшие видео в очередь:
  ```cmd
  python worker.py --reset-stale
  ```

## 4. Что проверять в первую очередь

### 4.1. Правильность разбиения видео на минибатлы

В дашборде, вкладка **«Минибатлы и очередь»**:

- у исходного видео указано `Найдено минибатлов`;
- в карточке минибатла отображаются `источник`, `серия`, `фрагмент start–end`;
- в списке должна быть отдельная карточка на каждую серию.

Если видео с двумя минибатлами определилось как одна серия или наоборот:

1. Проверьте `split_note` у видео в таблице очереди.
2. Откройте `config.py` и настройте:
   - `SERIES_BREAK_GAP_SEC` — пауза между сериями (по умолчанию 10 минут);
   - `MULTI_MINIBATTLE_VIDEO_DURATION_SEC` — длина ролика, после которой включается дополнительная эвристика;
   - `SERIES_DURATION_SPLIT_MIN_GAP_SEC` — минимальная пауза для split по длине (по умолчанию 4 минуты);
   - `MIN_MATCHES_PER_SERIES`;
   - `MAX_MATCHES_PER_MINIBATTLE = 9`.
3. Перезапустите видео с `--force`.

Если автоматика ошибается на конкретном ролике, лучше поправить константы и переобработать, а не редактировать БД вручную.

### 4.2. Ростер

В карточке минибатла:

- должно быть 4–6 игроков на команду и не больше 12 суммарно;
- позиции `GK/DF/MF/FW` и номера контроллеров должны выглядеть разумно;
- если игроков меньше 4 или появились мусорные имена — проверьте ROI `overlay`/`lineup` и качество кадра.

Плашка участников — главный источник имён. Если OCR прочитал мусор, исправьте это через **«Игроки и алиасы»** после обработки или перекалибруйте `overlay`.

### 4.3. Сборные

Разрешены **только 14 команд**:

`Япония 1`, `Япония 2`, `Италия`, `Германия`, `Аргентина`, `Бразилия`, `Камерун`, `Мексика`, `Монголия`, `Сенегал`, `Гвинея`, `Англия`, `Тайланд`, `Корея`.

Особое внимание:

- `Япония` без номера **не распознаётся автоматически** — это неоднозначно между `Япония 1` и `Япония 2`; такой матч должен уйти в проверку;
- если в войсе говорят «Тайланд/Таиланд» — оба варианта поддержаны;
- сборная, которой нет в списке, не должна приниматься парсером. Если увидели старую сборную в старом отчёте — это данные, созданные до обновления списка; переобработайте видео.

### 4.4. Финальные табло и счёт

В Review Mode для каждого матча есть скриншот финального табло. Проверьте:

- счёт совпадает;
- число голов в таймлайне совпадает со счётом;
- нет матча, который на самом деле является фрагментом другого.

### 4.5. Авторы голов, ассисты, привозы

В Review Mode:

1. откройте минибатл со статусом `needs_review`;
2. просмотрите таймлайн голов и цитаты;
3. поправьте автора/ассиста/привоз через выпадающие списки из ростера;
4. изменения сразу пересобирают MVP, сводку и Markdown-отчёт;
5. нажмите «Подтвердить весь минибатл → manual_verified».

Если отчёт нужно пересобрать отдельно (например, после Merge Players), используй кнопку **«Пересобрать отчёт и MVP»** внизу Review Mode.

Если атрибуция не названа в войсе, автоматика оставляет поле пустым и отправляет матч в проверку. Не выдумывайте автора только ради заполненности.

### 4.6. Дубли игроков

1. Вкладка **«Игроки и алиасы»**.
2. Проверьте дубли, поправьте канонические имена и алиасы.
3. Используйте **Merge Players**: источник удаляется, все ростера, матчи, голы, ассисты, привозы, MVP и линейки переезжают на целевого игрока.
4. После merge проверьте карточку игрока и при необходимости нажмите «Пересобрать отчёт и MVP» в Review Mode — иначе старый Markdown сохранит прежние имена.

## 5. Регулярный чек-лист после каждого крупного запуска

- [ ] Все 10 шаблонов цифр на месте.
- [ ] В очереди нет зависших `processing` старше 12 часов.
- [ ] Для длинных видео проверено число найденных минибатлов.
- [ ] У каждого минибатла 4–6 игроков на сторону (максимум 12).
- [ ] Сборные только из белого списка.
- [ ] Скриншоты финальных табло читаемы и счёт совпадает.
- [ ] Матчи со спорными голами отправлены в `needs_review` и подтверждены вручную.
- [ ] Дубли игроков объединены.
- [ ] `python worker.py` завершился с кодом 0; при `--limit 0` проверен лог на ошибки.

## 6. Что делать при сбоях

| Симптом | Что проверить |
|---|---|
| «No matches detected» | калибровка anchor, порог зелёного поля, шаблоны цифр |
| Нет шаблонов цифр | `--capture-digit`, кадры с нужной цифрой |
| Неверный счёт | confidence, стабильность 3 сек, шаблоны 0–9 |
| Два минибатла слиплись | `SERIES_BREAK_GAP_SEC`, `MULTI_MINIBATTLE_VIDEO_DURATION_SEC`, `split_note` |
| Один минибатл разрезан | увеличьте порог длительности/паузы, проверьте разбиение |
| Мусор в ростере | ROI overlay/lineup, качество видео, чистка имён и Merge Players |
| Не распознаны авторы | review-цитаты, алиасы игроков, hotwords Whisper |
| Ошибка ffmpeg | `ffmpeg -version`, `GOAL3_FFMPEG`, права на temp |
| Зависло `processing` | `python worker.py --reset-stale --stale-hours 0` |

Лог: `data/logs/pipeline.log`.
